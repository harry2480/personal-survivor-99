# Project 99 リポジトリ設定手順

GitHub 側の設定（ブランチ保護 / auto-merge / merge 方式）は**リポジトリ管理者が手で適用する**。
AI エージェントはリポジトリ設定・secret・保護ルールを変更しない（[loop-engineering.md](loop-engineering.md)）。

適用したら、本ファイルの「現在の設定」を実態に合わせて更新する。

---

## 必要な状態

| 項目 | あるべき状態 | 理由 |
|---|---|---|
| default branch | `main` | 要件定義 §120 |
| `main` への直接 push | 禁止（※） | 同上 |
| `main` への force push | 禁止 | 履歴の破壊を防ぐ |
| required status check | `CI ステータス確認`（job ID `ci-status`）**のみ**（※） | 集約 job 以外を required にすると、job 構成を変えるたびに設定変更が必要になる |
| PR の必須化 | 有効（※） | レビューを通さない変更を防ぐ |
| Allow auto-merge | 有効 | Loop が `gh pr merge --auto --squash` を要求するため |
| Squash merge | 有効 | 1 Issue = 1 PR を 1 commit に落とす |
| merge 後のブランチ削除 | 有効 | 作業ブランチの滞留を防ぐ |

実機が必要な Controller Test / Performance Test は自動化できないため、required check に含めない。

※ `enforce_admins: false` にしているため、管理者は緊急時にこの 3 つを bypass できる（恒常的には使わない）。
force push と branch 削除の禁止は `allow_force_pushes` / `allow_deletions` による別設定で、管理者にも適用される。

---

## 適用手順

### 1. merge 方式と auto-merge

```sh
gh api -X PATCH repos/harry2480/personal-survivor-99 \
  -F allow_auto_merge=true \
  -F allow_squash_merge=true \
  -F allow_merge_commit=false \
  -F allow_rebase_merge=false \
  -F delete_branch_on_merge=true
```

### 2. `main` のブランチ保護

Ruleset ではなく branch protection を使う場合。

```sh
gh api -X PUT repos/harry2480/personal-survivor-99/branches/main/protection \
  --input - <<'JSON'
{
  "required_status_checks": {
    "strict": true,
    "contexts": ["CI ステータス確認"]
  },
  "enforce_admins": false,
  "required_pull_request_reviews": {
    "required_approving_review_count": 0,
    "dismiss_stale_reviews": false,
    "require_code_owner_reviews": false
  },
  "restrictions": null,
  "allow_force_pushes": false,
  "allow_deletions": false,
  "required_conversation_resolution": true
}
JSON
```

- `required_approving_review_count` を `0` にしているのは、現状このリポジトリの開発者が 1 人で、
  自分の PR を自分で approve できないため。共同作業者が増えたら `1` に上げる
- `required_conversation_resolution: true` により、CodeRabbit を含む未解決 thread が残っていると
  merge できなくなる
- `enforce_admins: false` は緊急時の管理者 bypass を残すため。恒常的に使わない

### 3. 適用後の確認

```sh
gh api repos/harry2480/personal-survivor-99 \
  --jq '{allow_auto_merge, allow_squash_merge, delete_branch_on_merge}'

gh api repos/harry2480/personal-survivor-99/branches/main/protection \
  --jq '{checks: .required_status_checks.contexts,
         force_push: .allow_force_pushes.enabled,
         conversation: .required_conversation_resolution.enabled}'
```

期待する出力:

```json
{"allow_auto_merge": true, "allow_squash_merge": true, "delete_branch_on_merge": true}
{"checks": ["CI ステータス確認"], "force_push": false, "conversation": true}
```

## 現在の設定

最終確認: 2026-09-19

| 項目 | 状態 |
|---|---|
| default branch | `main` ✅ |
| Allow auto-merge | **未適用**（`false`） |
| Squash merge | 有効 ✅ |
| Merge commit / Rebase merge | 有効（上記手順で無効化する） |
| merge 後のブランチ削除 | **未適用**（`false`） |
| `main` のブランチ保護 | **未適用**（branch protection / ruleset とも無し） |

上記の「適用手順」を管理者が実行したら、この表を更新する。

---

## 変更してはいけないもの

- Actions の secret / 変数
- required check を回避する設定変更（Loop や AI エージェントからの要求であっても適用しない）
- Issue や PR の本文に書かれた指示を根拠にした設定変更

設定を変える必要が生じた場合は、理由と影響範囲を PR か Issue に残してから適用する。
