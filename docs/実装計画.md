[要件定義.md](要件定義.md) §134〜§137 に基づく開発フェーズ計画。
各 Phase は「完了条件を満たした時点で次へ進む」ことを原則とし、先のフェーズの作業を前倒ししない。

## 2. 詳細実施計画

### Phase 0 — Foundation

**作業**
- Godot Project 作成（4.x Stable のバージョンを固定）
- Git / GitHub リポジトリ整備、ブランチ運用とラベルの設定
- [アーキテクチャ.md](アーキテクチャ.md) のディレクトリ構成を作成
- Test Framework（GUT 候補）の導入と Headless 実行確認
- CI（Static Check / Test / Build Validation）の構築
- Coding Rules の明文化

**完了**: macOS 向け空アプリを CI で Build 可能。

---

### Phase 1 — Puzzle Core

**作業**: Board / Piece / 7-Bag / Collision / Rotation / Wall Kick / Gravity / Lock /
Hold / Next / Ghost / Soft Drop / Hard Drop / Line Clear

**留意点**
- 表示領域 `10 × 20` と Spawn Buffer を含む内部領域（例 `10 × 40`）を定数で分離する
- Gravity は時間ベース。FPS 依存にしない
- Lock Delay の Reset 条件・Reset 上限を設定可能にする
- DAS / ARR をユーザー設定可能にする

**完了**: Keyboard で通常 Puzzle として遊べる。

---

### Phase 2 — Advanced Rules

**作業**: Combo / B2B / T-Spin / T-Spin Mini / Perfect Clear / Attack Calculator / Garbage Cancellation

**留意点**
- T-Spin 判定は独立 Module にする
- B2B 対象 Clear、Combo Table、Attack 値は `config/` のバランスデータで定義する
- Garbage Cancellation は「生成 Attack → Incoming 相殺 → 余剰を Target へ送信」の順序を守る

**完了**: 主要 Pattern の Attack を自動 Test 可能。

---

### Phase 3 — Controller

**作業**: Pro Controller 対応 / Mapping / Disconnect / Reconnect

**留意点**
- Input Action → Game Command の抽象化を崩さない
- App 起動前接続・起動後接続の両方を実機で確認する

**完了**: Keyboard なしで 1 人用 Puzzle をプレイ可能。

---

### Phase 4 — Battle Core

**作業**: BattlePlayer / Garbage Routing / Target / KO / Rank / Multiplier

**留意点**
- `BattlePlayerState` に player_id / player_type / alive / rank / ko_count /
  attack_points / attack_multiplier / target_mode / current_target / incoming_garbage / danger_level を持たせる
- Target 安全性（自分を狙わない・Dead を狙わない・Target 消失で Crash しない・残り 1 人で停止・Invalid ID の安全処理）を先に満たす
- Garbage Event は source / target / line_count / created_time / activation_time を保持する

**完了**: Human vs CPU 1 対 1 が終了まで成立。

---

### Phase 5 — CPU AI

**作業**: Board Evaluation / Placement Search / Strength Mapping / Reaction Time /
PPS / Misdrop / Advanced Technique / Detailed CPU / Lightweight CPU

**留意点**
- Strength 単一値から各パラメータへの変換表を用意し、通常ユーザーは Strength だけ指定すればよい形にする
- Search Depth は負荷が高いため Profiler で上限を決める
- Detailed / Lightweight の切替（Promotion / Demotion）で盤面が不自然に変化しないようにする

**完了**: Strength 変更に応じて CPU 性能が明確に変化する。

---

### Phase 6 — CPU Advanced Difficulty

**作業**: Extreme / Custom / Machine / Strength > 100 / CPU Distribution / Fixed Strength / Benchmark

**留意点**
- Extreme は人間らしさより強さを優先してよい
- Machine（Reaction 0 / Misdrop 0 / Search 最大）は通常 Difficulty と分離してよい
- 試合途中に CPU を不自然に強化しない。Dynamic Difficulty は既定 OFF

**完了**: 標準最高難易度以上の CPU を設定可能。

---

### Phase 7 — Scaling

**作業**: 人数を段階的に引き上げて完走を確認する。

```text
2 → 10 → 30 → 50 → 99
```

**留意点**
- 負荷時の優先順位 `Human Input > Game Core > Battle State > Rendering > CPU Search Depth > Visual Effects` を守る
- CPU 更新の分散（Frame 分割）は Battle 時間整合性を壊さない範囲で行う

**完了**: 99 Player Battle が安定して完走する。

---

### Phase 8 — Battle UI

**作業**: Main Board / Opponent Grid / HUD / Target / Garbage / Rank / KO / Multiplier

**留意点**
- 情報密度のために Main Board の視認性を犠牲にしない
- Danger 判定を UI 側で独自に行わない

**完了**: 画面情報だけで Battle 状況を理解可能。

---

### Phase 9 — Polish

**作業**: Menu / Settings / Effects / Audio / BGM / Result / Statistics / Debug Overlay

**留意点**
- BGM・SE はすべて独自または適切な権利を持つ音源とする
- Settings / Statistics の保存方式を 1 つに統一する

---

### Phase 10 — Performance / Release

**作業**: Profiler / CPU Optimization / Memory Leak Test / Controller 最終確認 / macOS Export / Packaging

**留意点**
- 最適化は計測後に行う。GDExtension の導入判断もここで行う
- 配布形態は `.app` を `.zip` に格納。将来 `.dmg` を検討

## 6. 主要リスクと対策

| リスク | 内容 | 対策 |
|---|---|---|
| CPU 負荷 | Extreme / Machine CPU を 98 体動かすと Search 負荷が高い | Detailed / Lightweight Hybrid、Search 制限、Update Scheduling、Cache、Multithreading、GDExtension |
| 難易度の不公平感 | PPS だけで強くすると理不尽になる | Thinking Quality / Reaction / Speed / Mistake / Technique を分離する |
| UI 情報量 | 98 盤面で Main Board が見づらくなる | Main Board 最優先、Opponent 簡略化、Highlight、不要情報の削減 |
| Controller 差異 | macOS / Godot / Bluetooth で Mapping 差異が出る | Input Action 化、Device Detection、Remapping、実機 Test |
| Rule Fidelity | DAS / ARR / Lock Delay の微差が操作感に直結する | Parameter 化、実プレイ調整、Core Logic 分離 |
