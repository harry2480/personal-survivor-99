# Project 99 永続化レイヤー設計方針

> 本プロジェクトにはデータベースがない。ローカルファイル（`user://`）と設定リソース（`config/`）への
> アクセスを本書の対象とし、規約を定める。

保存・読み込みは専用の Persistence モジュールに集約する。
Game Core / Battle / UI から `FileAccess` や `ConfigFile` を直接呼ばない。

---

## 1. 扱うデータの種類

| 種別 | 置き場所 | 書き換え | 内容 |
|---|---|---|---|
| Rule / Balance データ | `config/*.tres`, `config/defaults.json` | 開発者のみ（ビルドに同梱） | Gravity, Lock Delay, DAS, ARR, Attack Table, CPU Parameters 等 |
| User Settings | `user://settings.json` | 実行時 | Gameplay / Audio / Video / Input 設定 |
| Input Bindings | `user://settings.json`（同一ファイルに含めてよい） | 実行時 | Keyboard / Controller Mapping, Dead Zone |
| CPU Settings | `user://settings.json` | 実行時 | Preset, Strength, Min/Max, Variance, Advanced Parameters |
| Statistics | `user://stats.json` | 実行時 | 通算成績 |

**保存方式は 1 つに統一する。** JSON と `ConfigFile` を混在させない。

---

## 2. 基本パターン

```gdscript
# persistence/settings_repository.gd
class_name SettingsRepository
extends RefCounted

const SETTINGS_PATH: String = "user://settings.json"

func load_settings() -> GameSettings:
    if not FileAccess.file_exists(SETTINGS_PATH):
        return GameSettings.create_default()

    var file: FileAccess = FileAccess.open(SETTINGS_PATH, FileAccess.READ)
    if file == null:
        push_warning("Failed to open settings: %d" % FileAccess.get_open_error())
        return GameSettings.create_default()

    var parsed: Variant = JSON.parse_string(file.get_as_text())
    if typeof(parsed) != TYPE_DICTIONARY:
        push_warning("Settings file is corrupted. Falling back to defaults.")
        return GameSettings.create_default()

    return GameSettings.from_dict(parsed)

func save_settings(settings: GameSettings) -> Error:
    var file: FileAccess = FileAccess.open(SETTINGS_PATH, FileAccess.WRITE)
    if file == null:
        return FileAccess.get_open_error()
    file.store_string(JSON.stringify(settings.to_dict(), "\t"))
    return OK
```

## 3. 実装ルール

- **ファイル I/O を Repository 内に閉じ込める。** Game Core / Battle / CPU / UI から
  `FileAccess`・`ConfigFile`・`ResourceLoader` を直接呼ばない
- **`user://` 以外の絶対パスを書かない。** macOS のサンドボックス外パスに依存しない
- **読み込みは必ず失敗し得るものとして扱う。** ファイル無し・破損・型不一致・旧バージョンの
  4 ケースを想定し、いずれもデフォルト値へフォールバックして起動を継続する。保存データの破損でクラッシュさせない
- **バージョン番号を保存データに含める。** スキーマ変更時に移行または初期化を判断できるようにする
- **Dictionary をそのままアプリ内に持ち回らない。** 読み込み直後に `GameSettings` 等の
  型付きモデルへ変換し、保存時に `to_dict()` で戻す
- **検証はモデル側で行う。** 範囲外の値（負の DAS、Strength の異常値等）はモデルのファクトリで
  デフォルトへ丸める。Repository は I/O とパースの第一段エラーハンドリングのみを担当する
- **Battle 中に同期書き込みを行わない。** Statistics の更新は Battle 終了時などの区切りでまとめて保存する
- **Rule / Balance データ（`config/`）は実行時に書き換えない。** ユーザーが変更できる値は
  Settings 側へコピーして保持する

## 4. Statistics の保存対象

```text
Games Played
Wins
Top 10 Count
Average Rank
Total KO
Best KO
Total Lines
Quad Count
T-Spin Count
Perfect Clear Count
Play Time
Highest CPU Strength Defeated
```

集計は Battle 終了時の結果から算出し、Battle 中の一時値をそのまま書き出さない。

---

## 5. テスト

- 保存・読み込みは実ファイルに対して検証する（[テストガイドライン.md](テストガイドライン.md) の Integration Test 扱い）
- 最低限、以下を検証する
  - デフォルト生成 → 保存 → 読み込みで値が一致する
  - ファイルが存在しない場合にデフォルトで起動できる
  - 破損 JSON を与えた場合にクラッシュせずデフォルトへフォールバックする
  - 旧バージョンのデータを読んでもクラッシュしない
- テストで書き込む先はテスト用パスに切り替え、実ユーザーデータを破壊しない
