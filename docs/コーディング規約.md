# Project 99 コーディング規約

GDScript を書くときの具体的なルール。設計レベルの方針（レイヤー構造・責務分割・依存方向の考え方）は
[アーキテクチャ.md](アーキテクチャ.md)、UI の表記・見た目のルールは [スタイルガイド.md](スタイルガイド.md) を参照する。
本ファイルは「手を動かすときに迷ったら見る場所」として、命名・型・分割・Signal・Git の粒度まで落とし込む。

判断に迷う場合は [要件定義.md](要件定義.md) §127 を一次情報とする。

## 機械検証される規約

以下は `scripts/static-check.sh` が CI とローカルで検査する。**レビュー前に自分で通す。**

| 規約 | 検査 |
|---|---|
| 関数名・変数名・クラス名の命名 | `gdlint` |
| インデント・空行・行長などの整形 | `gdformat --check` |
| ファイル・ディレクトリが snake_case | 自前検査 |
| `core/` が上位レイヤーを参照しない | 自前検査（`res://` 参照の走査） |

残りは人間のレビューで見る。詳細は [品質チェック・テスト規約.md](品質チェック・テスト規約.md)。

## 命名規約

| 対象 | 規則 | 例 |
|---|---|---|
| ディレクトリ | snake_case | `core/rotation/` |
| ファイル（`.gd` / `.tscn` / `.tres`） | snake_case | `wall_kick_table.gd` |
| クラス（`class_name`） | PascalCase | `class_name WallKickTable` |
| 関数 | snake_case | `func try_rotate_cw() -> bool:` |
| 変数・引数 | snake_case | `var lock_delay_ms: int` |
| 定数 | SCREAMING_SNAKE_CASE | `const BOARD_WIDTH := 10` |
| enum 型名 / 値 | PascalCase / SCREAMING_SNAKE_CASE | `enum Rotation { SPAWN, RIGHT }` |
| Signal | snake_case の**過去形** | `signal line_cleared(count: int)` |
| 内部専用のメンバー | `_` 始まり | `var _elapsed_ms: float` |

- **ファイル名とその中の `class_name` を対応させる。** `wall_kick_table.gd` なら `WallKickTable`
- 略語を独自に作らない。`Garbage` を `gbg` のように縮めない
- 真偽値は述語として読める名前にする（`is_alive` / `has_hold` / `can_rotate`）
- 単位が曖昧になる値は名前に単位を入れる（`lock_delay_ms` / `gravity_cells_per_sec`）

## 型（Typed GDScript）

**型注釈は必須。** 変数・引数・戻り値すべてに付ける。

```gdscript
# OK
func calculate_attack(lines: int, combo: int, is_b2b: bool) -> int:
    var base: int = _line_attack_table[lines]
    return base + _combo_bonus(combo)


# NG（戻り値の型がない / 変数の型がない）
func calculate_attack(lines, combo, is_b2b):
    var base = _line_attack_table[lines]
    return base + _combo_bonus(combo)
```

- 戻り値のない関数も `-> void` を明示する
- 配列は要素型まで書く。`var opponents: Array[BattlePlayerState] = []`
- `Variant` は外部入力（JSON パース結果など）の受け口に限定し、**直後に型付きモデルへ変換する**
- `Dictionary` を状態の器として持ち回らない。状態は専用 Class / Resource として定義する
- 型が緩い箇所を残す場合は、理由をコメントで明記する

### Magic Number を書かない

数値は定数化するか、`config/` のバランスデータへ出す（[要件定義.md](要件定義.md) §38・§39）。

```gdscript
# NG
if elapsed > 0.5:
    _lock_piece()

# OK
if elapsed > _rules.lock_delay_sec:
    _lock_piece()
```

Gravity / Lock Delay / DAS / ARR / Attack / Combo Table / CPU Parameters は
**コードに固定しない。** `config/` のデータで定義する。

## `core/` の依存禁止事項

Game Core は以下を**参照しない**。`res://ui/` `res://scenes/` `res://audio/` `res://input/`
`res://battle/` `res://cpu/` への参照は `scripts/static-check.sh` が検出して落とす。

| 禁止 | 代わりに |
|---|---|
| UI / Audio / Animation | Signal で「起きた事実」を通知し、上位層に処理させる |
| Scene / Scene Tree / `get_node()` | 必要な値を引数・コンストラクタで受け取る |
| Controller（物理デバイス、ボタン番号） | Input Action → Game Command を経由した抽象コマンドを受け取る |
| File System | 設定は Resource / Dictionary として注入してもらう |
| Opponent Grid | Battle Layer が扱う |
| 実時間（`Time` / `Timer` / `await`） | 外部から渡される delta / tick で進める |
| グローバル乱数（`randi()` / `randf()`） | Seed 付き `RandomNumberGenerator` を注入して使う |

```gdscript
# NG: Core が Scene Tree と実時間に依存している
func update() -> void:
    await get_tree().create_timer(0.5).timeout
    _lock_piece()

# OK: 時間は外から渡される
func tick(delta_sec: float) -> void:
    _elapsed_sec += delta_sec
    if _elapsed_sec >= _rules.lock_delay_sec:
        _lock_piece()
```

同様に `battle/` `cpu/` は `ui/` `scenes/` `audio/` を参照しない。
**依存方向 `Presentation → Battle → Game Core` を逆転させない。**

## Signal

層をまたぐ通知は Signal で行い、直接参照を増やさない。

```gdscript
signal line_cleared(count: int, is_t_spin: bool)
signal player_ko(victim_id: int, attacker_id: int)
```

- **名前は「起きた事実」の過去形にする。** `line_cleared` であって `clear_lines` ではない
- 引数にも型を付ける
- **受け手に処理を指示しない。** `show_effect` のような命令形の Signal を作らない
- 下位層は上位層の Signal を購読しない。Core が UI の Signal を待つ形にしない
- 接続はできるだけ上位層でまとめて行い、どこで繋がっているか追える状態にする

使う Event の一覧は [アーキテクチャ.md](アーキテクチャ.md) の Event / Signal 設計を参照。

## ファイル分割

- **1 ファイル 1 責務。** 「Board の状態」と「Line Clear の判定」を同じファイルに詰めない
- 巨大 Manager を作らない。`game_manager.gd` に何でも足していく形を避ける
- 置き場所は [要件定義.md](要件定義.md) §119 のディレクトリ構成に従う。迷ったら
  「この処理はどのレイヤーの責務か」を先に決めてからファイルを作る
- Autoload（Singleton）は最小限にする。現状 `SceneRouter` のみ。増やす場合は理由を PR に書く
- Public API を明示する。外から呼ばれない関数・変数は `_` 始まりにする
- 1 ファイルが 300 行を超えたら、責務が混ざっていないか一度疑う（機械的な上限ではない）

## コメント

- **何をしているか**ではなく、**なぜそうしたか**を書く。コードを読めば分かることは書かない
- 要件由来の制約は節番号を添える（`# 要件定義 §42: 相殺は Incoming を先に消費する`）
- 一時的な回避策には理由と、解消条件を書く

Godot の設定ファイル（`project.godot` / `*.tres` / `export_presets.cfg`）の
**コメントは `;` で始める。** `#` で書くとその行以降が黙って読み捨てられ、設定が効かなくなる。
これは `scripts/static-check.sh` が検査する。

## Git

### ブランチ

default branch は `main`。**`main` への直接 commit / push は禁止**（[要件定義.md](要件定義.md) §120）。

```text
feature/*    機能追加
fix/*        バグ修正
refactor/*   挙動を変えない整理
perf/*       性能改善
chore/*      ビルド・設定・雑務
```

### Commit Convention

[要件定義.md](要件定義.md) §121 に従う。

| prefix | 用途 |
|---|---|
| `feat:` | 機能追加 |
| `fix:` | バグ修正 |
| `refactor:` | 挙動を変えない整理 |
| `perf:` | 性能改善 |
| `test:` | テストの追加・修正 |
| `docs:` | ドキュメントのみの変更 |
| `chore:` | ビルド・設定・依存・雑務 |

- 1 行目は 50 字程度で、**何をしたか**を書く
- 本文には**なぜ必要だったか**と、**どう検証したか**を書く
- 1 commit 1 目的。無関係な整形を混ぜない

```text
fix: Lock Delay の Reset 上限が効かない問題を直す

Reset 回数のカウンタを接地のたびに初期化していたため、
横移動を続けると無限に接地をやり直せる状態だった。

検証: tests/core/test_lock_delay.gd に再現ケースを追加（修正前は失敗）
```

### PR

- 1 Issue = 1 PR を原則にする
- PR 本文に**実際に実行した検証とその結果**を書く。実行していないものを書かない
- `scripts/static-check.sh` `scripts/verify-godot.sh` `scripts/run-tests.sh` を通してから出す
