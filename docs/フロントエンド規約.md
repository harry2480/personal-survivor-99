# Project 99 UI 実装規約

> 本書は Godot の **Presentation Layer（`scenes/` `ui/` `audio/`）**の実装規約を定める。
> 全体設計は [アーキテクチャ.md](アーキテクチャ.md)、画面構成と非機能要件は
> [フロントエンドアーキテクチャ.md](フロントエンドアーキテクチャ.md) を参照。

---

## ディレクトリ責務

| ディレクトリ | 責務 |
|---|---|
| `scenes/` | 画面単位の Scene（boot / main_menu / battle / settings / result） |
| `ui/board/` | Player Board の描画 |
| `ui/opponent/` | Opponent Grid・縮小盤面 |
| `ui/hud/` | Remaining / Rank / KO / Target / Multiplier 等の HUD |
| `ui/menu/` | メニュー・Settings UI |
| `ui/components/` | 汎用 UI パーツ |
| `audio/` | AudioManager / MusicManager |
| `assets/themes/` | Godot Theme リソース |

---

## View とゲームロジックの分離

- **UI から Game Core / Battle の内部状態を直接変更しない。** 変更は Command または Signal を経由する
- View は「受け取った状態を描画する」ことだけを行う。勝敗・Danger・Rank 等の**判定を UI 側で行わない**
- View に盤面ルール（Collision、Rotation、Line Clear 判定など）を書かない
- Battle Scene では `BattleController` を唯一の接続点とし、各 View が Battle Layer を直接掴まない

```gdscript
# NG: View が Core の状態を直接書き換える
board_state.cells[y][x] = CellType.EMPTY

# OK: View は Signal を購読して描画のみ更新する
func _on_line_cleared(rows: Array[int]) -> void:
    _play_clear_animation(rows)
```

---

## Signal の扱い

- 層をまたぐ通知は Signal で行う。下位層は上位層の Signal を購読しない
- Signal は「起きた事実」を渡す。受け手の処理内容を指示しない
- Signal の接続・解除は対になるライフサイクル（`_ready` / `_exit_tree`）で行い、解除漏れを作らない
- 毎フレームの全状態ポーリングで描画を更新しない。イベント駆動を基本とする

---

## Scene / Node 設計

- Scene は自己完結させる。親の構造を前提にした `get_parent()` や絶対パスの `get_node()` を書かない
- 外部から渡す値は `@export` か初期化メソッドで受け取る
- 再利用する表示要素は `ui/components/` に切り出し、画面 Scene に埋め込まない
- 巨大 Scene・巨大スクリプトを作らない。責務ごとに分割する
- Autoload（Singleton）は AudioManager 等の必要最小限にとどめる

---

## 描画パフォーマンス

- Opponent Grid は毎フレーム 98 盤面を再構築しない。差分更新または更新間引きを行う
- ノードの動的生成・破棄をループ内で繰り返さない。プールを使う
- `GPUParticles2D` 等の演出は負荷時に削減できるよう、EffectLayer にまとめて制御可能にする
- 負荷時の削減順: Visual Effects → Opponent 詳細 → Opponent 更新頻度。**Player Board と Human Input は削らない**

---

## スタイル・レイアウト

- 色・フォント・サイズは Theme リソースに集約する。Scene 内で直接 `Color(...)` を書かない
- Magic Number（座標・サイズ・間隔）を直書きしない。定数または Theme の定数を使う
- レイアウトは Control の Anchor / Container を使い、解像度差を吸収する。座標の絶対値でレイアウトしない
- 詳細は [スタイルガイド.md](スタイルガイド.md) を参照

---

## 入力の扱い

- UI は **Input Action 名**のみを扱う。物理ボタン番号・スキャンコードを直接参照しない
- ゲームプレイ中の入力処理は `input/` 層に集約し、View 側で `Input.is_key_pressed()` を直接使わない
- Pause / メニュー操作もキーボードとコントローラーの両方で成立させる

---

## Audio

- SE の発火は Signal 起点で行い、View の描画処理の中に直接書かない
- SE Event は最低限、Move / Rotate / Hold / Soft Drop / Hard Drop / Lock / Line Clear /
  High-value Clear / Combo / Garbage Send / Garbage Receive / Target Change / Danger / KO / Victory / Defeat を定義する
- BGM は Menu / Battle Normal / Battle Mid / Battle Late / Final / Victory / Defeat の状態別に管理する
- 音源はすべて独自または適切な権利を持つものを使用する
