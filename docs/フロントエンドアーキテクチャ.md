# Project 99 Presentation（UI）実装方針

> 本書は Web フロントエンドではなく、**Godot の Presentation Layer（Scene / UI / Audio）**の実装方針を定める。
> レイヤー全体の設計は [アーキテクチャ.md](アーキテクチャ.md)、細かな実装ルールは [フロントエンド規約.md](フロントエンド規約.md) を参照。

## 1. 概要

99 人戦では最大 99 個の盤面を同時に描画する。情報量が極端に多いため、
**「自分の盤面の視認性」を最優先に据えたうえで、対戦状況を把握できる密度に抑える**ことを基本方針とする。

## 2. 技術スタック

| 区分 | 採用 |
|---|---|
| Engine | Godot Engine 4.x Stable |
| Renderer | Godot 標準 2D Renderer（Metal API を直接利用しない） |
| Language | Typed GDScript |
| 主な Node | Node2D / Control / CanvasItem / Sprite2D / TextureRect / Label / AnimationPlayer / Tween / GPUParticles2D |
| テーマ | Godot Theme リソース（`assets/themes/`） |
| Audio | Godot Audio（`audio/audio_manager.gd`, `audio/music_manager.gd`） |

## 3. ディレクトリ構成

```text
scenes/                     # 画面単位の Scene
├── boot/
├── main_menu/
├── battle/
├── settings/
└── result/

ui/                         # 再利用される View コンポーネント
├── board/                  # Player Board 描画
├── opponent/               # Opponent Grid / 縮小盤面
├── hud/                    # Remaining / Rank / KO / Target / Multiplier 等
├── menu/                   # メニュー・設定 UI
└── components/             # 汎用パーツ（ゲージ、ラベル、ボタン等）

audio/
├── audio_manager.gd
└── music_manager.gd

assets/
├── fonts/
├── images/
├── music/
├── se/
└── themes/
```

### Battle Scene の構成

```text
Battle
├── PlayerBoardView
├── OpponentGrid
├── HUD
├── EffectLayer
├── AudioManager
└── BattleController
```

`BattleController` が Battle Layer と View の橋渡しを行う唯一の窓口。各 View は Signal を購読して自分の描画のみを更新する。

## 4. 画面レイアウト

```text
┌───────────────────────────────┐
│       Opponent Boards         │
│                               │
│ HOLD    PLAYER BOARD    NEXT  │
│                               │
│       Opponent Boards         │
│                               │
│ Rank / KO / Target / Power    │
└───────────────────────────────┘
```

### 4.1 Main Player Board

画面上で**最も高い視認性**を確保する。表示要素:

- Fixed Blocks
- Active Piece
- Ghost Piece
- Incoming Garbage（受信予告）
- Danger State

### 4.2 Opponent Grid

最大 98 個を表示する。最低限の表示:

- Board（縮小表示）
- Alive / Dead
- Target 状態

必要に応じて Danger / Attack Power / Attacker / Badge 相当情報を追加する。

### 4.3 HUD

最低限の表示項目:

```text
Remaining Players
Rank
KO Count
Attack Multiplier
Target Mode
Current Target
Incoming Garbage
Attackers Count
Hold
Next
```

NEXT は UI 上で最低 5 個表示する（内部 Queue はそれ以上を保持する）。

## 5. UI 優先順位

```text
1. Player Board
2. Incoming Garbage
3. Next / Hold
4. Target
5. Danger
6. Remaining Players
7. KO / Multiplier
8. Opponent詳細
```

**情報密度のために Main Board の視認性を犠牲にしない。** 表示追加時は必ずこの順位で取捨選択する。

## 6. Battle Progression 演出

残存人数の代表的閾値で段階変化させる。

```text
99 → 50 → 20 → 10 → 5 → 2
```

変化対象: BGM / Background / Particle / UI / Animation / SE / CPU Simulation Priority

## 7. 画面遷移

```text
Boot → MainMenu → (Play) → Battle → Result → MainMenu
                     └── Settings
```

- 起動時にログインやネット接続を要求しない
- Pause 中は Player / CPU Simulation と Timer を停止し、Audio は Pause または減衰する。
  Pause メニューは `Resume / Restart / Settings / Quit to Menu`
- Battle 開始時に長時間の UI Freeze を起こさない。必要な状態は Loading 段階で準備する

## 8. 非機能要件

### パフォーマンス

- 99 人戦で平均 **60 FPS 以上**。対応可能なら 120 FPS+ を許容する
- Game Simulation 結果を Render FPS によって変化させない
- 描画負荷が高い場合の削減順は Visual Effects → Opponent 詳細表示 → Opponent 更新頻度。
  Player Board と Human Input は最後まで削らない
- Opponent Grid は毎フレーム全 98 盤面を再構築しない（差分更新 / 更新間引き）

### 解像度

主対象は Mac の 16:10。以下でレイアウト破綻を避け、Retina を考慮する。

```text
1280 × 800
1440 × 900
1920 × 1200
2560 × 1600
```

### アクセシビリティ

- Keyboard Remap / Controller Remap
- Audio Control（Master / BGM / SE）
- Fullscreen / Window 切替
- Screen Shake 軽減オプション
- **色だけに依存しない Target 表示 / Danger 表示**（形状・枠線・アイコンを併用する）
- 将来: Color Blind Theme、UI Scale

## 9. Settings 画面の構成

| カテゴリ | 項目 |
|---|---|
| Gameplay | DAS / ARR / Soft Drop Speed / Ghost / CPU Difficulty / CPU Custom Settings |
| Audio | Master / BGM / SE |
| Video | Fullscreen / Window Mode / VSync / FPS Limit |
| Input | Keyboard Mapping / Controller Mapping / Dead Zone |

CPU Difficulty は Preset（Easy / Normal / Hard / Very Hard / Extreme / Custom）を既定とし、
Custom 選択時のみ Strength / Min / Max / Variation を表示、さらに Advanced 展開で個別パラメータを編集可能にする。

## 10. Debug Overlay

開発ビルドで表示する候補:

```text
FPS / Frame Time / Alive Players / Detailed CPU Count / Lightweight CPU Count /
Average CPU Strength / Highest CPU Strength / Memory / Active Garbage / Seed / Game Time
```

## 11. 実装順序

Presentation は [実装計画.md](実装計画.md) の Phase 8（Battle UI）と Phase 9（Polish）で本格実装する。
それ以前の Phase では、動作確認に必要な最小限の描画にとどめ、演出へ工数を割かない。

1. Player Board 描画（Phase 1 時点の最小実装）
2. HUD の必須項目
3. Opponent Grid
4. Target / Garbage / Multiplier 表示
5. Menu / Settings / Result
6. Effects / Audio / BGM / Battle Progression 演出
